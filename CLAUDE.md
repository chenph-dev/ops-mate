## Project Overview

**ops-mate** is a Wails v2 desktop application — Go backend + React/TypeScript frontend. Wails uses Go's `embed` to bundle the compiled frontend (`frontend/dist`) into a single native binary, replacing Electron with a lightweight WebView2.

## Common Commands

```bash
# Live development (hot reload for both Go and frontend)
wails dev

# Build production binary
wails build

# Build for a specific platform
wails build -platform windows/amd64
wails build -platform darwin/universal

# Frontend-only commands (run from frontend/)
pnpm install          # install dependencies (use pnpm, not npm)
pnpm dev              # Vite dev server (standalone, no Go bridge)
pnpm build            # tsc type-check + vite production build
```

## Architecture

### Go Backend (`main.go`, `app.go`)

- `App` struct holds a `context.Context` set at startup. Any Go type with exported methods can be bound to the frontend.
- Binding happens in `main.go` via `Bind: []any{ ... }` with one entry per bound handler type (see `internal/handler/`). Every **exported** method on a bound type is automatically callable from the frontend.
- The `//go:embed all:frontend/dist` directive in `main.go` embeds the built frontend assets — `frontend/dist` must exist before `wails build` works.
- Window is configured as **frameless** (custom title bar chrome built in the frontend) but **resizable** (1024×768 default).

### Frontend (`frontend/`)

- React 19 + TypeScript + Vite + Ant Design 6 + react-router-dom 7.
- Entry point: `frontend/src/main.tsx` → `frontend/src/App.tsx` (provides antd `ConfigProvider` with dark theme + `RouterProvider`).
- **Routing**: `react-router-dom` with `HashRouter` (required for Wails — BrowserRouter breaks on embedded assets). Routes defined in `frontend/src/components/AppLayout/menuConfig.tsx` as a single source of truth that drives both the sidebar `<Menu>` and `createHashRouter()`. Layout shell with `<Outlet/>` lives in `frontend/src/components/AppLayout/index.tsx`. Pages are React.lazy-loaded from `frontend/src/pages/<Name>/index.tsx`.
- **Frameless window**: the app uses `-webkit-app-region: drag` on the Sider logo area and Header (see `AppLayout/index.module.css`) to provide a custom title bar drag region. Interactive elements must use `no-drag`.
- `frontend/wailsjs/` is **auto-generated by Wails** — never edit it. It contains:
  - `go/<package>/<Type>.js` / `.d.ts` (e.g. `go/hosts/HostsHandler.js`) — proxy functions that call Go methods via `window['go']['<package>']['<Type>']['MethodName']`
  - `runtime/` — Wails runtime for events, dialogs, window control, etc.
- When adding a new Go method, regenerate the bridge with `wails dev` (or `wails generate module`), then import from the matching `@wailsjs/go/<package>/<Type>` module.
- **Adding a new page**: create `pages/<Name>/index.tsx`, then add a `RouteItem` to the `routes` array in `menuConfig.tsx` — menu and routing update automatically.

### Build Output (`build/`)

- `bin/` — final compiled binary
- `darwin/` — macOS `Info.plist` (customize app metadata)
- `windows/` — icon, manifest, NSIS installer config
- `build/appicon.png` — source icon used to generate `icon.ico`

### Key Configuration

- `wails.json` — Wails project config (app name, build commands, author). Frontend build/install/dev commands are defined here and invoked by `wails dev` / `wails build`.
- `go.mod` pins the Wails framework directly (`github.com/wailsapp/wails/v2 v2.12.0`); `wails.json` holds the app-level build config.

## Adding a New Backend Method

1. Add an exported method to a bound handler struct in Go (e.g., `func (h *HostsHandler) MyMethod(arg string) string`).
2. Run `wails dev` (or `wails generate module`) to regenerate the matching `frontend/wailsjs/go/<package>/<Type>.js` and `.d.ts`.
3. Import and call from React: `import { MyMethod } from '@wailsjs/go/<package>/<Type>'` → `const result = await MyMethod('input')`.

## Internationalization (i18n)

- 前端使用 `react-i18next`，**默认简体中文**（`zh-CN`），Header 右上角可切换到 `en-US`，选择持久化到 `localStorage`（key: `ops-mate-lang`）。
- 语言资源在 `frontend/src/locales/{zh-CN,en-US}/`，按功能模块分命名空间（`common`/`menu`/`hosts`/`terminal`/`sftp`/`ai`/`config`/`audit`/`about`），**两个语言文件的结构必须保持一致**。
- i18n 实例在 `frontend/src/i18n/index.ts`（`defaultNS: 'common'`）。
- 新增 UI 文案：不要硬编码中文，组件内用 `useTranslation('<ns>')` 后 `t('key')`，hooks 内用 `i18n.t('ns:key')`，并同步补充两个语言资源。
- **key 不要带命名空间前缀**：`useTranslation('menu')` 已绑定 ns，`t('hosts')` 即可；写成 `t('menu.hosts')` 会因在 menu 下找不到 `menu.hosts` 而原样返回 key 字符串（`menuConfig` 的 `label` 只存相对 key 如 `'hosts'`）。
- 插值用 `{{var}}`，如 `t('hosts.tabs.maxWarning', { count: MAX_TABS })`。
- antd 内置组件文案跟随当前语言（`App.tsx` 中 `ConfigProvider locale` 动态切换）。
- 后端经 Wails 透传的错误文本一期不做翻译，原样展示；`data/commands.json` 是命令补全数据，不翻译。

## Conventions

- Package manager is **pnpm** (lockfile and workspace config present). Use `pnpm install`, not `npm install`.
- `frontend/dist` is gitignored — it is a build artifact, not source.
- Go module name is `ops-mate` (no domain prefix).
